# Changelog

## 0.4.0

- Made source validation execute safe host-supported behavior tests and report unavailable PowerShell coverage explicitly.
- Simplified bootstrap to read-only preflight, fixed project-scoped watcher paths and worktree validation, and reduced duplicated guidance.
- Added the Portable Adoption Kit, reference environment, and re-entry guide for a portable, reproducible personal AI coding baseline.
- Added cross-platform reproduction utilities and source-level reproduction tests while preserving user ownership of accounts, configuration, and explicit installation decisions.
- Added project-scoped Graphify watcher adapters for Linux, macOS, and Windows, with watcher-only automatic refresh and documented native-platform acceptance boundaries.
- Clarified that runtime management, self-healing doctor tooling, and unattended installers remain outside the Harness.

## 0.3.0

- Made the README the adoption entry point for the thin Harness.
- Added a safe, manual adoption workflow for global, repository, and subsystem instructions plus project-owned verification.
- Added a practical daily Codex usage guide covering goals, subagents, worktrees, review, `codex exec`, hooks, verification, and optional OMX.
- Clarified the ownership boundary between Native Codex, Superpowers, the Harness, and optional OMX.
- Extended source validation to require the new documentation contracts.

## 0.2.0 (historical; superseded by the thin-harness refactor)

- Added E1 execution policy and E2 change-aware verification routing contracts.
- Added opt-in, turn-level E3 telemetry hooks with privacy boundaries.
- Added H1 doctor, H2 safe install/update, H3 safe uninstall, and H4 Behavioral Lab.
- Kept project verification, stateful runtime operations, telemetry analysis, model routing, and Codex behavioral execution outside the Harness runtime.
